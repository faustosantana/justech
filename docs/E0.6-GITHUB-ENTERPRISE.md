**Repositorio oficial:** `https://github.com/odoo/enterprise`  
**Rama requerida:** `19.0` (alineada con imagen `odoo:19.0-20260619`)  
**Estado E0.6:** Procedimiento documentado — clonación diferida a Fase E1

---

## Por qué GitHub (no descargas manuales)

Odoo documenta dos métodos oficiales para obtener código Enterprise:

1. **Git** — `github.com/odoo/enterprise` (recomendado para actualizaciones)
2. **Tarball** — [odoo.com/page/download](https://www.odoo.com/page/download)

Para una implementación profesional mantenible, **Git es el método preferido**: `git pull` para parches, trazabilidad de commit, rollback por tag.

---

## Procedimiento oficial: vincular GitHub con la suscripción

### Paso 1 — Cuenta GitHub

1. Crear o usar cuenta GitHub existente (recomendado: cuenta técnica Justech, no personal)
2. Anotar el **username** exacto (case-sensitive)

### Paso 2 — Portal Odoo

1. Iniciar sesión en [https://www.odoo.com/my/subscriptions](https://www.odoo.com/my/subscriptions)
2. Abrir suscripción **`M260616306091776`**
3. Buscar sección **"GitHub Users"** o **"Access to GitHub"**
4. Agregar el username de GitHub
5. Guardar cambios

### Paso 3 — Esperar acceso (5–30 minutos)

Odoo otorga acceso de lectura al repositorio privado `odoo/enterprise`.

### Paso 4 — Verificar acceso (obligatorio antes de E1)

Desde el navegador, con la cuenta GitHub vinculada:

```
https://github.com/odoo/enterprise
```

| Resultado | Significado |
|-----------|-------------|
| Repositorio visible, rama `19.0` existe | ✅ Listo para clonar |
| HTTP 404 | ❌ Username no vinculado o suscripción inactiva |

### Paso 5 — Token para servidor (VPS)

En el VPS no hay navegador. Usar **GitHub Personal Access Token (PAT)**:

1. GitHub → Settings → Developer settings → Personal access tokens
2. Fine-grained token (recomendado) o classic con scope `repo` (solo lectura)
3. Resource owner: tu cuenta
4. Repository access: **Only select** → `odoo/enterprise` (si visible)
5. Permissions: Contents → Read-only

**Almacenar en VPS:**

```bash
# NO commitear — solo en servidor
/opt/odoo-projects/hellenia/config/credentials/github.env
chmod 600 config/credentials/github.env
```

```ini
# github.env (ejemplo)
GITHUB_USER=justech-odoo
GITHUB_TOKEN=ghp_xxxxxxxxxxxx
```

### Paso 6 — Clonación (Fase E1 — script `clone-enterprise.sh`)

```bash
git clone https://${GITHUB_USER}:${GITHUB_TOKEN}@github.com/odoo/enterprise.git \
  --branch 19.0 --depth 1 /opt/odoo-projects/hellenia/enterprise
```

> El directorio `enterprise/` es un **repositorio Git independiente**. No forma parte del repo Justech.

## Lo que NO hacer

| Acción | Razón |
|--------|-------|
| Commitear `enterprise/` en repo Justech | Viola OPL-1.0; repo público |
| Usar OAuth "Connect GitHub" en CI genérico | No otorga acceso a org `odoo` |
| Clonar rama `master` o `19.3` sin plan | Desalineación con imagen Docker pinneada |
| Modificar archivos dentro `enterprise/` | Se pierden en `git pull` |
