## Por qué Git (no descargas manuales)

## Autenticación en VPS — análisis de métodos

El VPS no tiene navegador. Se evaluaron métodos para clonar `odoo/enterprise` sin almacenar un PAT permanentemente.

### Comparativa (ordenada por seguridad)

| Método | ¿Aplica a `odoo/enterprise`? | Seguridad | Decisión Hellenia |
|--------|------------------------------|-----------|-------------------|
| **1. Deploy Key** | ❌ No | Alta para repos propios | **Descartado** — Deploy Keys solo las configura el admin del repo. `odoo/enterprise` pertenece a la organización Odoo; el cliente recibe acceso de lectura vía suscripción, no permisos de administración del repo |
| **2. SSH Key (cuenta GitHub)** | ✅ Sí | **Alta** — clave ed25519 dedicada en VPS; sin token en archivo; revocable desde GitHub | **✅ Método preferido** |
| **3. Git Credential Manager** | ⚠️ Parcial | Media — diseñado para estaciones de trabajo interactivas | **Descartado** — no es el patrón recomendado para servidores headless Linux |
| **4. GitHub App** | ❌ No | Alta en repos propios | **Descartado** — requiere instalar la App en la organización `odoo`, lo cual no está disponible para suscriptores |
| **5. PAT (solo lectura)** | ✅ Sí | Media-baja — secreto de larga duración en disco | **Fallback** — solo si SSH no es viable |

### Método preferido: SSH Key dedicada

Odoo documenta clone SSH oficialmente:

```bash
$ git clone --branch 19.0 --single-branch git@github.com:odoo/enterprise.git
```

— [Source install — Git](https://www.odoo.com/documentation/19.0/administration/on_premise/source.html)

#### Configuración (Cursor ejecutará en E1 vía SSH)

```bash
# 1. Generar clave dedicada (sin passphrase para automatización servidor)
ssh-keygen -t ed25519 -C "hellenia-vps-enterprise" \
  -f /opt/odoo-projects/hellenia/config/credentials/github_ed25519 -N ""

chmod 700 /opt/odoo-projects/hellenia/config/credentials
chmod 600 /opt/odoo-projects/hellenia/config/credentials/github_ed25519
chmod 644 /opt/odoo-projects/hellenia/config/credentials/github_ed25519.pub

# 2. Usuario agrega github_ed25519.pub en GitHub:
#    Settings → SSH and GPG keys → New SSH key → Title: hellenia-vps-enterprise

# 3. SSH config para usar clave dedicada solo con github.com
cat > /opt/odoo-projects/hellenia/config/credentials/ssh_config << 'EOF'
Host github.com
  HostName github.com
  User git
  IdentityFile /opt/odoo-projects/hellenia/config/credentials/github_ed25519
  IdentitiesOnly yes
EOF
chmod 600 /opt/odoo-projects/hellenia/config/credentials/ssh_config

# 4. Verificar acceso (dry-run)
GIT_SSH_COMMAND="ssh -F /opt/odoo-projects/hellenia/config/credentials/ssh_config" \
  git ls-remote git@github.com:odoo/enterprise.git refs/heads/19.0
```

#### Ventajas sobre PAT

| Aspecto | SSH Key | PAT en archivo |
|---------|---------|----------------|
| Secreto en disco | Clave privada (estándar servidor) | Token con scope `repo` |
| Revocación | Eliminar key en GitHub | Revocar token |
| Scope | Solo autenticación SSH | Acceso API según permisos token |
| Rotación | Generar nueva key | Regenerar token + actualizar archivo |
| Almacenamiento | `config/credentials/` chmod 600 | `github.env` — **evitado** |

### Fallback: PAT de solo lectura

Solo si SSH falla tras diagnóstico:

- Fine-grained PAT, scope Contents Read-only, repo `odoo/enterprise`
- Almacenar temporalmente; rotar tras migrar a SSH
- Ver `config/credentials/github.env.example` (marcado como fallback)

## Clonación (Fase E1 — `scripts/clone-enterprise.sh`)

```bash
GIT_SSH_COMMAND="ssh -F /opt/odoo-projects/hellenia/config/credentials/ssh_config" \
  git clone git@github.com:odoo/enterprise.git \
  --branch 19.0 --depth 1 /opt/odoo-projects/hellenia/enterprise
```

> `enterprise/` es repositorio Git **independiente**. No forma parte del repo Justech.

## Lo que NO hacer

| Acción | Razón |
|--------|-------|
| Commitear `enterprise/` en Justech | Viola OPL-1.0 |
| Deploy Key en `odoo/enterprise` | No aplicable — repo de terceros |
| PAT permanente sin rotación | Menos seguro que SSH dedicada |
| Clonar rama incorrecta | Desalineación con imagen Docker |
| Modificar archivos en `enterprise/` | Se pierden en `git pull` |
