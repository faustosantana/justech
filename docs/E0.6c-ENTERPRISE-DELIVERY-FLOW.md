**Objetivo:** Que el usuario **no tenga que usar SCP ni SSH** al VPS; Cursor ejecuta validación y (tras aprobación E1a) el pipeline completo en DEV.

| Prueba | Resultado |
|--------|-----------|
| VPS → `https://www.odoo.com/page/download` | ✅ HTTP 200 (HTML público) |
| VPS → `nightly.odoo.com` Community 19 | ✅ HTTP 200 |
| VPS → Enterprise **sin autenticación** | ❌ **No existe URL pública permanente** |
| `curl` / `wget` en VPS | ✅ Disponibles |

### Conclusión oficial

Odoo documenta que la descarga Enterprise requiere:

> *"logged in as a paying on-premise customer or partner"*  
> — [Packaged installers](https://www.odoo.com/documentation/19.0/administration/on_premise/packages.html)

**No hay API ni URL wget estable** para Enterprise 19. El portal genera enlaces de descarga **vinculados a la sesión** del navegador (o enlace único del email de compra). Por diseño de seguridad, `curl` sin cookies de sesión devuelve HTML de login o error — no el tarball.

| Escenario | ¿Automático desde VPS? |
|-----------|------------------------|
| URL pública Community nightly | ✅ Sí (no aplica a Enterprise) |
| URL copiada del navegador tras login (enlace directo al `.tar.gz`) | ✅ **Semi-automático** — ver Flujo A |
| Archivo descargado en PC del usuario | ✅ **Semi-automático** — ver Flujo B |
| Login interactivo en VPS | ❌ No recomendado / no preparado |
| Sin enlace ni archivo | ⚠️ **Único paso manual:** descargar ZIP/TAR en odoo.com — ver Flujo C |

## Flujos de entrega (elige uno)

### Flujo A — Enlace temporal (preferido, sin tocar VPS)

**Tu parte (≈2 minutos):**

1. Login en [odoo.com](https://www.odoo.com) con la cuenta de la suscripción `M260616306091776`
2. Abrir [odoo.com/page/download](https://www.odoo.com/page/download)
3. Odoo **19** → **Enterprise** → fila **Sources** → **Download**
4. **Clic derecho** en el botón/enlace de descarga → **Copiar dirección del enlace**
5. Pegar la URL en el chat de Cursor (no commitear en Git; enlaces expiran en minutos)

**Cursor ejecuta en VPS:**

```bash
/opt/odoo-projects/hellenia/scripts/download-enterprise-portal.sh 'PEGAR_URL_AQUI'
```

El script descarga con `curl`, valida integridad y estructura, y deja el archivo en:

```
/opt/odoo-projects/hellenia/downloads/enterprise/odoo-19.0-enterprise-sources.tar.gz
```

Si el enlace expiró: repetir pasos 3–5 con URL nueva.

---

### Flujo B — Archivo vía Cursor (sin SCP del usuario)

**Tu parte:**

1. Descargar Enterprise Sources 19 desde el portal (mismos pasos que Flujo A, pero guardar archivo)
2. **Adjuntar** el `.tar.gz` o `.zip` al chat de Cursor (o colocarlo en el workspace del agente)

**Cursor ejecuta:**

```bash
# Desde entorno agente — sube al VPS y valida
HELLENIA_SSH_KEY=/ruta/clave scripts/receive-enterprise-archive.sh --upload /ruta/local/archivo.tar.gz
```

O si el archivo ya está en el VPS:

```bash
scripts/receive-enterprise-archive.sh /ruta/en/vps/archivo.tar.gz
```

**No necesitas** abrir terminal, SCP ni SSH al VPS.

---

### Flujo C — Manual documentado (fallback)

Si los flujos A y B fallan (portal sin Download, enlace roto, archivo corrupto):

| Paso | Quién | Acción |
|------|-------|--------|
| 1 | **Usuario** | Descargar ZIP/TAR desde [odoo.com/page/download](https://www.odoo.com/page/download) |
| 2 | **Usuario** | Entregar archivo a Cursor (adjunto) **o** enlace temporal (Flujo A) |
| 3 | **Cursor** | `receive-enterprise-archive.sh` o `download-enterprise-portal.sh` |
| 4 | **Cursor** | `e1a-portal-pipeline.sh --validate-only` |

**No hay tercera vía mágica:** Odoo no publica Enterprise en nightly ni en GitHub sin permisos. El único paso humano inevitable es **obtener el archivo desde el portal autenticado** (o email de compra).

## Validación automática (sin instalar)

Script principal:

```bash
scripts/validate-enterprise-archive.sh <archivo> --report
```

Implementación: `scripts/lib/validate_enterprise_archive.py`

| Check | Descripción |
|-------|-------------|
| `integrity` | ZIP `testzip()` / TAR lectura completa — detecta corrupción |
| `size` | Tamaño mínimo (>500 KB) |
| `structure` | Raíz de addons Enterprise con `web_enterprise/__manifest__.py` |
| `module_web_enterprise` | Módulo obligatorio presente |
| `version_compat` | `version` en manifest empieza por `19.0` |
| `module_count` | Conteo de módulos con `__manifest__.py` (warn si <10) |
| `archive_type` | Warn si parece tarball Community completo (`odoo-bin`, etc.) |
| `module_l10n_do_*` | Opcional — warn si ausente (E1c futuro) |
| `sha256` | Hash del archivo (trazabilidad en reporte JSON) |

Reporte JSON guardado en: `logs/validate/enterprise-<timestamp>.json`

Pipeline solo validación (estado actual — **E1a no aprobado**):

```bash
scripts/e1a-portal-pipeline.sh --validate-only [archivo]
```
